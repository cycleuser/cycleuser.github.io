Strata 本地部署 Qwen3.8-Flash-Next：哪些显卡能跑？速度如何？多少钱？多大显存？

发布于 Mon 05 October 2026 | 22 分钟 | 标签 本地部署 Strata 显卡 Qwen3.8 量化

Qwen3.8-Flash-Next 是一个稀疏混合专家（MoE）模型，总参数约 1250 亿 [1]。结构上为 48 层，每层 512 个专家，合计 24576 个专家；每个 token 由路由（router）选中其中 10 个参与计算，其余专家不使用。除专家之外，还有注意力与 DeltaNet 混合层、门控残差（gated residual，即 hyper-connection）、共享专家、输出头，以及一个用于投机解码的 MTP 草稿层。参数量决定模型的存储占用，激活量才决定每个 token 的实际算力：这个模型激活比例很低，但全部专家都必须有地方常驻。

常规做法是把模型的全部参数（含全部 24576 个专家）一次性加载进显存，所以这类 125B 模型要占用几百 GB 显存，只能放在服务器上跑。个人电脑和家庭配置下，另一种思路是统一内存（UMA，例如 Apple 芯片、Strix Halo、DGX Spark），把整个模型完整加载进内存，让 CPU 与 GPU 共用。

Strata 的做法不同：不完整加载，而是按访问频率把模型分层拆开，只把每个 token 都会用到、以及访问最频繁的部分留在显存。具体拆法是——显存放注意力与 DeltaNet、门控残差、路由、共享专家、输出头、MTP 草稿层、KV 缓存，以及用「专家缓存」常驻的最热专家；全部 24576 个专家放内存，CPU 在 GPU 运算的同时并行计算没进显存的那部分；SSD 放 28.8GB 的 n-gram 查找表，每个 token 只读其中几行。显存每多 1GB 大约多放 700 个专家，所以显存容量比算力更影响速度。

下面把 Strata 官方文档和 876 条 issue/PR 反馈里跟显卡有关的部分梳理一遍，给出一份能直接照着选卡的清单。

模型结构与量化占用

结构要点：

  • 48 层，每层 512 个专家，合计 24576 个专家，每个 token 激活 10 个。
  • 上下文窗口训练到 262144 个 token，可用 rope（yarn）扩展到 384K / 512K / 1M（实验）。
  • 自带 MTP 草稿层做投机解码；可选 0.9GB 的视觉编码器读图。

表 1 量化档位与占用（总下载体积、专家占用的内存，以及内存+显存占用）[3]：

档位 精度 总下载体积 专家占内存 内存+显存 说明
Q2_0 约 2 bit 66GB 约 34GB 37.6GB 速度最快，质量一般
IQ2_XS 约 2 bit 68GB 约 36GB 39.2GB 速度接近 Q2_0，质量略好，官方推荐
IQ3_XXS 约 3 bit 76GB 约 43GB 47.0GB 速度较慢，质量较好
IQ3_S 约 3 bit 约 84GB 约 50GB 54.8GB 速度最慢，质量最好，在公开测试上与完整模型相当
Coder IQ1_M 1.89 bit/原始参数 58GB 约 23GB 29.6GB 每层保留 256 个专家，偏重代码，32GB 内存可运行
UD-IQ4_XS 约 4 bit 94GB 约 59.5GB 约 84GB 需 48GB 以上内存；不足则从 SSD 流式读取，速度下降
UD-Q4_K_XL 约 4 bit 111GB 约 72GB 约 96GB 实验档，需 48GB 以上内存与 NVMe 固态硬盘；不足则流式读取

Coder 版把每层专家从 512 减到 256，每个 token 仍激活 10 个；官方公布的成绩约为完整模型的 SWE-bench Verified 91.3%、LiveCodeBench v6 98.7%。

Strata 的优化设计

Strata 的引擎内嵌了 llama.cpp / ggml 的部分实现：i-quant 量化格式、GPU 的反量化与点积内核、CPU 后端、视觉用的 mtmd 库、打包用的 gguf-py；思路还参考了 Splash、ninfer、HyperQwen [8][36]。在此之上，主要做了这些优化：

  • 专家缓存（expert cache）：按路由统计出的专家热度 profile 预填显存，运行时随对话内容把冷热专家换入换出，显存用满为止。
  • GPU 与 CPU 并行：进入显存的专家由 GPU 计算，没进的由 CPU 用 AVX-512 / AVX2 内核原地计算，两边同时进行、互不等待。
  • 量化矩阵乘（MMQ）：专家直接用量化内核做矩阵乘，不先反量化成 FP16，省显存也省带宽。
  • 预填充分块：长 prompt 最多按 8192 个 token 一块读取；当前层算注意力时，下一层的专家已经通过 PCIe 预取过来。
  • 投机解码：模型自带的 MTP 层一次草拟最多 3 个 token，48 层一次前向全部校验，平均每次前向产出 2.4–3.2 个 token；重复内容（改代码、引用原文）再由 prompt lookup 草拟最多 5 个，输出质量与不用草稿时一致。
  • KV 分级：64K 上下文起，KV 缓存放内存，只把注意力要读的部分常驻显存（--kv-resident 32768）；可选的 k8v4 再省约 23% 的 KV。
  • 低内存模式：专家可从 SSD 上的 experts.bin 或直接从不入内存的 GGUF 映射读取（--mmap-experts、--resident-experts、--resident-budget-gib），让大显存、小内存的机器也能跑起来。
  • 长上下文：用 rope（yarn）把上下文从 262144 扩到 384K / 512K / 1M。

硬性要求

先区分「能运行」与「可用」：官方的最低门槛是 8GB 显存也能启动，但显存越小，能常驻显存的专家越少，越多专家要交给 CPU 甚至从 SSD 读取，速度会明显下降。8GB 卡属于「能跑，但慢到失去本地部署的意义」；显存建议 12GB 以上才有实际价值。下表是运行门槛（表 2）：

项目 要求
显卡 NVIDIA RTX 20 / 30 / 40 / 50 系；AMD 见 表 3。显存建议 12GB 以上，8GB 能启动但明显偏慢
内存 32GB 起；64GB 可运行全部档位（各档占用见 表 1）
磁盘 模型约 70–80GB，加草稿层约 6GB；建议 NVMe 固态硬盘
CPU x86-64 且支持 AVX2（近 8 年的 Intel / AMD 桌面 CPU 基本都满足）
系统 Windows 10 / 11 或 Linux；NVIDIA 驱动 580 以上

图 1　价格 × 解码速度 × 显存（竖版，23 款；RTX 5090 因远高于其余、会压缩其余点，未画入）。横轴为 2026-10-05 参考价格（元），纵轴为解码速度（tokens/s），气泡大小表示显存容量；图中每张卡标注「型号 + 显存」，价格读横轴、速度读纵轴，颜色区分 NVIDIA / AMD / Intel / Tesla（RTX 3080 / 2080 Ti 速度为估算）。价格为 2026-10-05 实抓挂牌价，非成交价，仅供横向比较。

以上参考价来自近期报价（2026-09 下旬至 2026-10-05），价格波动频繁，实际成交价请以下单时为准。三条经验：显存容量比算力更重要（Tesla P40 依靠 24GB 常驻专家，可跑到 30 tokens/s 以上）；内存与 SSD 是隐性瓶颈（内存不足会频繁读取磁盘）；二手服务器卡价格低但限制多（无视频输出、被动散热、属实验性通道）。

需要注意的问题

社区反馈中，显卡本身可用，但限制与问题不少，选卡前建议了解：

  • RX 7900 XTX 在个别 ROCm 版本上会掉到 1 tokens/s 以下（[33]），换 ROCm 版本可解。
  • AMD 卡在 Linux 桌面同卡运行时，显存预留不足会触发 OOM 杀进程，需要加大预留（[34]）。
  • RDNA2（gfx1030，对应 RX 6800 / 6800 XT / 6900 XT / 6950 XT）没有 hipBLASLt 调优表，prompt 读取偏慢；UD-Q4_K_XL 组合有间歇性卡死（[35]）。
  • 0.1.39 在 RX 6800 上有 12–22% 的解码回归，加 STRATA_SH_STREAM=0 恢复（[27]）。
  • Intel Arc 目前仍是实验通道，需要源码编译，Windows 还没有原生路径（[7]）。
  • 不支持的架构：Polaris（gfx803，如 RX 580 / RX 570 / RX 480）不在任何通道内。AMD 主后端要求 wave32（RDNA），wave64 只有 gfx906 的兼容层，gfx9 的 gfx900 也仅是新增的实验构建；Polaris 连这个都没有。同时 ROCm 早已放弃 Polaris（gfx803），无法编译出引擎。市面上所谓「16GB RX 580」属非官方魔改卡，仍是 gfx803，同样不支持。
