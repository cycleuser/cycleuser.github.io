Project Maya 把 GLM-5.3-Flash 和 DeepSeek-V4.1-Flash-1017 装到本地电脑

发布于 Sun 25 October 2026 | 19 分钟 | 标签 Project Maya Strata GLM-5.3-Flash DeepSeek 本地部署

Project Maya（ https://github.com/mw00/project-maya ）是 GitHub 上 @mw00（Peasant Smith）创建并主导的仓库，MIT 授权，共同维护者是 @needmorevram。它做的事情说得具体一点：把 GLM-5.3-Flash（321 B 参数，每 token 激活约 18 B）和 DeepSeek-V4.1-Flash-1017（748 B 参数）放进普通电脑，最低一张显卡起步，当然也还是需要大内存。

先说清来源。

一、和 Strata 的关系

中秋以来，开源模型框架里，最受关注的大概是Strata。

Strata 原版解决的是小显存+大内存运行大模型的提速问题：稀疏的模型，权重放不进显存，可又得随时能取。但是和 Halogen 类似， Strata 原版只聚焦于 Qwen3.8-flash-next 这一个模型。当然这也好理解，因为这个模型目前基本做到了性能、开销和速度等各方面最均衡的平衡，是本地部署能兼顾质量、性能和速度的一个平衡点。

可是有的朋友，他可能需要更小的模型，更快的速度，而不是那么在意模型的长链任务、上下文和复杂问题的解决能力，于是针对小模型，有了 PolyStrata，能扩展 Strata 支持的模型范围到更多类型和尺寸的 MoE 小模型，比如 Gemma4-26b-a4b、Ornith1.5-35b-a3b等等，也能塞进 8 GB 显卡+32GB 内存。

还有另一个方向，就是运行比 Qwen3.8-flash-next 更大规模的模型，这就是 Project Maya 关注的方向了，针对 GLM-5.3-Flash 和 DeepSeek-V4.1-Flash-1017，给各自配一个引擎（GLM 走 maya，DeepSeek 走 maya-ds4）。

覆盖面上 Maya 比 PolyStrata 窄得多，就这两个模型加几种社区量化。硬件方面支持比较多：NVIDIA 从 Volta（V100）往上都能装，社区表里连 2 张 Tesla P40 24 GB 这种 Pascal 老卡都有，另有 4 张 T4 16 GB 和 4 张 Tesla T10 15 GB；AMD 属于实验性（RX 7900 XT/XTX、Radeon AI PRO R9700、Strix Halo 和 Gorgon Halo），GLM 在 AMD 上只读文字，DeepSeek 连图一起。Linux 为主，Windows 10/11 实验性支持，明确不支持 WSL2，AMD 要 ROCm 7。

我的设备主要都是 AMD 的，比如 Ai Max 395（Strix Halo）和 7900 XTX，而且内存只有64G，因此没办法实际运行 Maya了。下文所有体积、速度、质量数字都出自开源项目自己的官方文档、量化跑分记录和 README 里那张社区实测表，社区表里每一行都写着机型、档位、上下文长度、版本号和问题编号。他们的模型文件也在 96 GB 到 508 GB 之间，大家自己的电脑，如果内存和显存总数不够，就可能比较吃力。

三、精度降低带来的性能损失

Maya 官方对性能测试，是参照官方原版为基线，分两个口径分别报，仓库里 bench/results/ 当中有四个文件一份一档，详细的方法写在里面。

一个口径是选择题，五道零样本任务（ARC-Easy、ARC-Challenge、HellaSwag、WinoGrande、PIQA），每题 400 问，FP8 原模型和量化档做的是同一批题，打分照 lm-evaluation-harness 那套（取对数似然最大的选项，选项长度不同就按长度归一）。FP8 原模型是逐层在 PyTorch 里跑的，量化档走 Maya 自己的引擎。结果就是表 1 那列保留率：最低的 Maya-S24 也有 97.7%，Maya-L 99.2%，HellaSwag 和 PIQA 两题跟原模型同分。

五、硬盘空间要留足够了

先看硬盘占用。

图 4 模型文件占用，竖线是一块 1 TB 固态硬盘，Maya 明确要求放高速 NVMe

GLM 一档 94.7 到 156.3 GB，DeepSeek 一档 340 到 508 GB，图片编码器另外 1.1 GB。装 DeepSeek 的 8 bit GGUF，你得先空出 500 GB 以上的高速空间。

内存这一项比显存更容易被低估。他们文档写着 32 GB 就能跑，紧跟着的一句是引擎启动时锁住除约 6 GB 之外的全部空闲内存当专家层，别的程序那会儿基本分不到什么，而且启动要几分钟，引擎在锁内存和加热缓存。

你要是打算开着编辑器和浏览器一起干活，64 GB 都不宽裕，所以我没有在自己机器上尝试这个框架。

如果要共享同一台机器，办法仓库自己也给了：配置里写 "idle_unload_s": 900，一刻钟没请求就整个卸掉，一张 3090 上跑 Maya-S24 能交回 22.9 GB 显存和 79 GB 内存，代价是下一次请求先等一分钟左右加载。

根据官方项目中的一个案例数据，一张 3090 加 64 GB 内存跑 DeepSeek，读提示约 50 token/s，写答案 4 到 5 token/s。以我的配置，虽然使用 Strata 能有40tokens/s，使用 PolyStrata 更是有可能达到150 tokens/s，用 Maya 的话，可能就只有个位数了。

六、和 PolyStrata 怎么比

跟 PolyStrata 比，有两件事得先说清楚。

先说模型覆盖：PolyStrata 认 10 个模型，其中七个在 8 GB 显卡上能运行流畅，这些小尺寸模型，比如Ornith1.5、Gemma4 26b等，其实足够一些简单任务以及长链工作了，就是人睡觉之后你让他一直做一些事情，工具调用什么的，实际上是能凑合用的。

Maya 只把两个特别大的当目标，最小的档也要 94.7 GB 文件。所以谁更合适，取决于你要的是「笔记本上有个能用的模型」还是「就是要更强的两个大模型」；指名要 GLM-5.3-Flash 或 DeepSeek-V4.1-Flash-1017。

还有一处口径上的不同：Maya 把量化档做成自己的产品，四档都从 FP8 权重带校准重做，每档配一份跑分文件；PolyStrata 基本读社区现成的 GGUF，量的时候拿 llama.cpp 和 Q8_0 当尺子。前者的好处是质量有出处，代价是文件必须是它认的那几种，你手上已有的权重不一定在里面。

七、安装过程对付看看吧

git clone https://github.com/mw00/project-maya.git && cd project-maya
./setup.sh

一路回车就是推荐选项，Windows 换成 START-MAYA.bat。安装程序会把每一次下载的来源、大小和确切的 curl 命令打出来再问要不要下，跟它要用的文件全部对 sha256；已经下过就不重下，--gguf-dir 可以直接用它认得的已有文件。装完开 http://127.0.0.1:8080，浏览器里有聊天、有把每张显卡里装了什么列出来的 Monitor、有改上下文和端口的设置。想让它把显卡让出来给别人用，配 idle_unload_s，配上 STRATA_GLM_SLOT_KEEP=1 之后重加载还能接上原来那段对话（一次实测重载 1,690 个 token 里的 1,630 个）。

接口这边跟得上现在这些编程助手：/v1 是 OpenAI 兼容，/v1/messages 是 Anthropic 兼容（接 Claude Code 就一句 ANTHROPIC_BASE_URL=http://127.0.0.1:8080），/v1/responses 支持文字加图片的会话、流式、函数工具调用、按 JSON schema 校验输出、可取消可重放的后台任务。工具调用是边写边流出来的，长提示读到哪了也可以要（"return_progress": true）。别的地址上的网页想调它，得先在配置里把那个地址列进 cors_origins，不然浏览器拦着；要从局域网连过来，./maya.sh --setup --host 0.0.0.0 --api-key <密钥>，文档连着强调一定要设密钥。聊天里能贴图，思考档分 Off / Low / High / Max，--parallel 4 之后最多同时答 8 个请求，面板上会写着此刻在写几个答案。

出问题先跑 ./maya.sh --report，它把硬件、配置和引擎打出的速度行写成 maya-report.txt，不往任何地方发。文档里 FAQ 也实在，「慢而且固态一直在忙」的答案就是内存不够放专家，关掉程序或者加内存；Windows 上「回答突然慢好几倍」的原因是显卡太满被系统挪去了内存，解法是给它多留点空闲。

八、写在最后

Maya 比原版 Strata 能跑更多种模型，这是事实。Strata 原引擎是围着一个模型做的，Maya 把 GLM 5.3 Flash 和 DeepSeek V4 Flash 都收了进来，还自己做了四档量化、每档附一份跑分文件，量化方法和测量脚本都在仓库里，谁都能重跑一遍看数字对不对。这一点上它比一般「能跑就行」的移植项目讲究。

可我写完这些数字，感觉增长的代价比增长的本事更值得掂量。要跑 321 B 的模型，代价是 94.7 到 156.3 GB 的文件、把内存锁到只剩 6 GB、每写一个 token 搬 2.4 GB 的专家；再加一级到 748 B 的 DeepSeek，代价跳到 340 到 508 GB 文件和约 230 GB 的显存加内存，一张 3090 加 64 GB 内存的机器上写答案只有每秒四五个 token。质量的账也不像选择题保留率那么好看：换成逐 token 的口径，Maya-S 每 6 步就有 1 步选错下一个 token，工具调用那一栏更是只有 76.5% 的一致率。

如果只是想让本地有个反应够快的模型，为「参数更多」把内存从 32 GB 堆到 96 GB、把固态清空 500 GB，换来的却依然是 20-30 tokens/s，这好像就没那么划算了。

毕竟同样的成本下，用原版 Strata 跑模型可能达到翻几倍的效果，用 PolyStrata 运行一些小规模的模型甚至还能更快几倍。
